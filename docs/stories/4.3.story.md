## Story
> Como cliente que acabou de confirmar um agendamento,
> Quero receber uma mensagem de confirmacao via WhatsApp com os detalhes do agendamento,
> Para que eu tenha um registro e o agente AI saiba do meu agendamento em conversas futuras.

## Acceptance Criteria

- [ ] AC1: Apos confirmacao do booking (POST /confirm), cliente recebe WhatsApp com mensagem: "Ola {nome}! Seu agendamento foi confirmado: {servico} em {data} as {horario}. Obrigado!"
- [ ] AC2: Mensagem de confirmacao registrada na tabela `message_log` com direction='outgoing' e type='booking_confirmation'
- [ ] AC3: Campo `confirmation_sent` atualizado para true e `confirmation_sent_at` preenchido na tabela `bookings`
- [ ] AC4: Se cliente ja existe como lead (busca por telefone), booking e vinculado ao lead existente via `lead_id`
- [ ] AC5: Se cliente e novo (telefone nao encontrado), lead e criado automaticamente com nome, telefone e tag "agendamento" e vinculado ao booking
- [ ] AC6: Endpoint `GET /api/bookings/by-phone/:phone` retorna agendamentos do cliente (para consulta do agente AI)
- [ ] AC7: Se envio WhatsApp falhar, booking permanece valido (confirmation_sent = false) — graceful degradation
- [ ] AC8: Retry automatico para envio de confirmacao (max 3 tentativas com delay progressivo)
- [ ] AC9: Webhook do agente (`webhook-messages/index.ts`) reconhece contexto de agendamento quando cliente responde sobre booking

## Scope

### IN Scope
- Trigger pos-booking: logica de envio WhatsApp no endpoint POST /confirm
- Template de mensagem de confirmacao
- Registro em message_log
- Atualizacao de confirmation_sent no booking
- Busca/criacao de lead por telefone
- Endpoint de consulta de bookings por telefone (para agente)
- Retry com backoff para envio de confirmacao
- Enriquecimento do webhook do agente com contexto de booking

### OUT of Scope
- Cancelamento de agendamento via WhatsApp
- Lembretes automaticos (ex: 24h antes do agendamento)
- Reagendamento via WhatsApp
- Dashboard de metricas de agendamento
- Notificacao para o admin quando novo agendamento chega

### Architecture Reference

**Evolution API sendText** [Source: server/src/services/evolutionApi.js]
```javascript
async sendText(instanceName, number, text) {
  // POST /message/sendText/{instanceName}
  // Payload: { number, text, delay: 1000, linkPreview: false }
}
```

**Message Log Insert Pattern** [Source: server/src/routes/messages.js]
```javascript
await supabase.from('message_log').insert({
  lead_id,
  tenant_id,
  direction: 'outgoing',
  message_type: 'text',
  content: message,
  whatsapp_instance: instanceName,
  sent_at: new Date().toISOString()
});
```

**Lead Creation Pattern** [Source: supabase/functions/webhook-messages/index.ts]
```javascript
const { data: newLead } = await supabase.from('leads').insert({
  name: pushName || phone,
  phone,
  tenant_id: tenantId,
  current_stage_id: firstStageId,
  tags: ['agendamento'],
  notes: 'Lead criado via agendamento publico'
}).select('id').single();
```

**Kestra Payload Pattern** [Source: supabase/functions/webhook-messages/index.ts]
```javascript
const formData = new FormData();
formData.append('tenantId', tenantId);
formData.append('leadId', leadId);
formData.append('phone', phone);
formData.append('incomingMessage', messageContent);
// Novo campo:
formData.append('upcomingBookings', JSON.stringify(upcomingBookings));
```

**Fire-and-Forget Pattern** [Source: supabase/functions/webhook-messages/index.ts]
```javascript
// Nao aguardar resposta — enviar e seguir
sendBookingConfirmation(booking, tenantId).catch(err => {
  console.error('Booking confirmation failed:', err.message);
});
```

**Retry Pattern** [Source: server/src/services/scheduler.js]
```javascript
const delays = [2000, 5000, 10000]; // 2s, 5s, 10s
for (let attempt = 0; attempt < 3; attempt++) {
  try {
    await evolutionApi.sendText(instance, phone, message);
    return true; // sucesso
  } catch (err) {
    if (attempt < 2) await new Promise(r => setTimeout(r, delays[attempt]));
  }
}
return false; // todas tentativas falharam
```

### Instancia WhatsApp Ativa

Para enviar a confirmacao, precisamos da instancia WhatsApp ativa do tenant:
```javascript
const { data: instance } = await supabase
  .from('whatsapp_instances')
  .select('instance_name')
  .eq('tenant_id', tenantId)
  .limit(1)
  .single();
```

Se nao houver instancia ativa, logar warning e pular envio (graceful degradation).

### Formato de Telefone para Evolution API

A Evolution API espera o numero no formato internacional:
- Armazenado no banco: `11999998888` (apenas digitos)
- Enviar para Evolution: `5511999998888` (com codigo do pais)
- Adicionar prefixo `55` se o numero nao comecar com ele
